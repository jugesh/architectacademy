Architect Academy · V4

Learn the problem.
Then design the system.

17 substantial lessons, including API Design. Move from a concrete problem to definitions, requirements, implementation choices, failure analysis, worked designs, and interview practice.

Learning path: begin with Networking, API Design and Security. Then study workload, storage and communication; add consistency, service boundaries and operational control. Finish with recovery, pipelines, observability and end-to-end designs. Each lesson links the specific prerequisites it assumes. These broad lessons complement the exact-topic V3 curriculum.

Networking & HTTP

Understand the layers beneath an API call before diagnosing connection failures, slow requests and gateway timeouts.

API Design

Contracts, HTTP semantics, security, reliability, and three complete API design cases.

Security & Identity

Build from one private order lookup to tokens, delegated access, tenant isolation, credential rotation and auditable decisions.

Scalability

Follow an order service from one instance to a load-balanced system. Learn to measure demand, find the constraint, and preserve correctness while adding capacity.

Databases

Build an order store step by step: access patterns, keys, indexes, transactions, replication, and partitioning. Follow the data before choosing a database brand.

Caching

Start with one repeated product lookup. Build a cache, then follow what happens when data changes, entries expire together, or the cache disappears.

Messaging

Begin with a slow receipt email in checkout. Learn queues and event logs, acknowledgements, duplicates, ordering, outbox/inbox patterns, and operational recovery.

Consistency & Distributed Transactions

Move from one transaction to replicated reads and multi-service workflows without confusing local atomicity, consistency models and business compensation.

Microservice Boundaries

Grow a modular order application into independently owned services without creating a distributed monolith.

Rate Limiting & Backpressure

Protect checkout from noisy clients and slow dependencies by distinguishing request rate, concurrency, queues, quotas and downstream demand.

Replication & Partitioning

Follow a growing order store through read replicas, failover, sharding keys, hot partitions and safe rebalancing.

Reliability

Follow a checkout request through slow services, lost responses and process crashes. Derive deadlines, retries, idempotency, circuit breakers and recovery from those failures.

Deployment & Runtime

Connect Java process behavior to container lifecycle, Kubernetes routing, rolling delivery and data-compatible rollback.

Disaster Recovery

Derive backup, failover, reconciliation and failback choices from acceptable downtime and data loss.

Search & Data Pipelines

Follow committed order changes into search and analytics, then handle duplicates, old events, backfills and rebuilds.

Observability

Start with a customer asking where an order went. Build a useful evidence trail from logs to metrics, traces, asynchronous work, audit records and actionable alerts.

End-to-End Design Practice

Apply the V4 foundations to six systems. Make each decision traceable to a requirement, invariant, failure or operating constraint.

What every lesson includes

A definition before advanced terminology; explicit prior knowledge; a running example; functional and non-functional requirements; diagrams and code fragments; Spring and AWS mappings; selection criteria; tricky cases; answered interviews; and annotated official references.
