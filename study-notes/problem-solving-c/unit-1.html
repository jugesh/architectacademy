Unit I · Problem Solving and Algorithm Development

Lakshita Bindal

1. Problems and instances

A computational problem describes a required input–output relationship; an instance supplies particular input. Example: sorting is a general problem; sorting [7,2,5] is an instance. Generalization expands the allowed inputs; a special case restricts them (e.g., sorting only distinct integers).

2. Types and classification

TypeExample
DecisionIs n prime? → yes/no
SearchFind a matching array element
OptimizationFind the shortest route
CountingHow many solutions exist?
Function/computationCalculate factorial

Classify by input size, constraints, exact versus approximate answers, tractability, and whether a solution always exists. Complexity classes such as P and NP concern decision problems; NP does not mean “not polynomial.”

3. Problem-solving cycle

  1. Understand: define inputs, outputs, constraints, edge cases and examples.
  2. Plan: decompose into subproblems; choose brute force, divide-and-conquer, greedy, dynamic programming or another justified approach.
  3. Execute: write pseudocode, select data structures, implement incrementally.
  4. Review: test, prove correctness, estimate time and space, improve.

4. Specification and contracts

Input specification: integer n, 0 ≤ n ≤ 12. Output specification: n!. Validation: reject non-integers and out-of-range values. Precondition: n is within the accepted range. Postcondition: result equals the product 1×2×…×n (0! = 1). Validation checks external input; preconditions state assumptions that the algorithm requires.

5. Algorithms: properties and format

An algorithm has specified inputs/outputs, unambiguous steps, finite termination, and executable operations. A standard description states name, purpose, inputs, outputs, preconditions, steps and postconditions.

Algorithm FACTORIAL(n)
Input: integer n ≥ 0
Output: n!
result ← 1
for i ← 2 to n:
    result ← result × i
return result

Correctness: after iteration i, result = i! (loop invariant); termination follows because i increases to n. Efficiency: O(n) time, O(1) auxiliary space. Big-O describes asymptotic upper bounds; distinguish worst, average and best cases. Array indexing is O(1), linear search O(n), binary search on sorted data O(log n).

Data structures matter: arrays allow direct indexing, hash tables typically offer expected O(1) lookup, stacks support LIFO tasks, queues support FIFO tasks and graphs model networks. The same problem can have different complexities with different structures.

Quick check

Why must binary search require sorted input? Because each comparison discards half of the search interval only when ordering guarantees where the target can lie.
