ANSWERED ADVANCED INTERVIEW BANK · 12 SCENARIOS

Distributed reliability: Senior Interview and Design Review

Answer before reading. Every question pairs a technical explanation with a verification exercise or architectural follow-up.

1. What is a deadline and how does it differ from timeout?

Explain the trade-off and test.

A timeout bounds one local wait; an end-to-end deadline is the latest acceptable completion for the operation. Downstream calls must use the remaining budget minus overhead and cleanup reserve. Independent full timeouts at each hop can outlast client interest and waste capacity.

Follow-up / exercise: Budget 900 ms across authentication, DB and payment service calls.

2. Why can retries multiply exponentially?

Explain the trade-off and test.

When each of several layers retries independently, leaf attempts are a product of each layer's attempt count. Three attempts at each of three levels can produce 27 leaf calls for one user request. Assign retry ownership, use jitter and budgets, propagate deadlines and ensure safe operation identity.

Follow-up / exercise: Simulate transient 503 responses during a database incident.

3. What is a circuit breaker good for?

Explain the trade-off and test.

A breaker temporarily limits calls to a dependency suspected to be failing, allowing recovery and protecting some resources. It is not a substitute for concurrency limits, queue control or deadlines, and may not open if slow successes cause overload. Choose a meaningful failure window and half-open trial policy.

Follow-up / exercise: Why might an API still exhaust threads with an apparently closed breaker?

4. What does a bulkhead isolate?

Explain the trade-off and test.

Separate concurrency or resource pools stop one dependency's slowdown from consuming all resources needed by others. Isolation can be by semaphore, queue, thread pool or workload priority. Too many pools waste capacity; too little isolation spreads failure.

Follow-up / exercise: Design checkout so recommendation service failure does not starve payment processing.

5. How do distributed leases fail?

Explain the trade-off and test.

A holder can pause beyond lease expiry; another owner acquires the lease, and the old holder resumes believing it still owns the resource. A monotonic fencing token checked at the resource boundary can reject stale owners. Timeouts and heartbeat success alone cannot establish exclusive state updates.

Follow-up / exercise: Construct an example involving a long JVM GC pause.

6. What is the difference between saga and distributed transaction?

Explain the trade-off and test.

A saga coordinates local commits and compensations across services with observable intermediate states. A global atomic transaction attempts a shared commit decision across participants, with coordination and availability costs. Sagas require durable workflow state, idempotent steps and manual reconciliation paths; compensation is not necessarily reversal.

Follow-up / exercise: Compare authorizing a payment and later issuing a refund.

7. Why can compensation itself fail?

Explain the trade-off and test.

An external refund can time out, inventory release can race with another reservation, and a cancellation notification cannot undo an email already delivered. Compensation steps therefore need retries, identities, time limits, visibility and a manual-review terminal state.

Follow-up / exercise: Design a saga that survives a failed refund provider.

8. What does eventual consistency require from a product?

Explain the trade-off and test.

The product must define which stale reads are acceptable, how users see pending states, when reconciliation occurs and which invariants are never violated. A vague eventual-consistency label does not answer what happens when an order shows PAID before inventory reserves.

Follow-up / exercise: Set a user-visible freshness and correction policy.

9. What does CAP actually address?

Explain the trade-off and test.

CAP frames the trade-off under a network partition between linearizable consistency and availability of operations in the formal model. It does not rank systems as simply two-of-three independent knobs, and it does not substitute for latency, durability or session-consistency analysis.

Follow-up / exercise: Describe behavior of a write when quorum cannot be reached.

10. What is an SLI versus SLO versus SLA?

Explain the trade-off and test.

An SLI is a measurement such as fraction of valid API requests completing successfully under a threshold. An SLO is the desired target over a window. An SLA is a contractual promise with terms and possible remedies. Define denominators, exclusions and aggregation before computing an error budget.

Follow-up / exercise: Calculate allowed failures for 99.9% of one million eligible requests.

11. How does load shedding improve reliability?

Explain the trade-off and test.

When service capacity is fixed, early rejection of low-priority or excess requests can protect critical work and avoid creating long timeout queues. It converts uncontrolled latent failure into a bounded, explicit overload contract. Caller retries must not immediately defeat the limit.

Follow-up / exercise: Plan graceful degradation during an inventory dependency slowdown.

12. How do you test distributed failure modes?

Explain the trade-off and test.

Inject network delays, dropped responses, duplicate messages, process crashes at persistence boundaries, partition loss and clock skew where relevant. Assert domain invariants and recovery time, not merely that endpoints returned a status. Use trace correlation and state reconciliation to verify outcomes.

Follow-up / exercise: What would falsify the claim that one logical order is never charged twice?
