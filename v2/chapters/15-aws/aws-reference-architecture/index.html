1. Landing zone and account boundaries

Use separate accounts or equivalent strong boundaries for production, nonproduction, security logging, and shared services when organizational scale warrants them. Apply AWS Organizations policies and identity design so production access is narrow and auditable. A service control policy constrains allowable account actions but does not grant IAM permissions. Centralize CloudTrail and security findings in a protected location. An infrastructure migration between AWS accounts includes identity, KMS, network endpoints, secrets, DNS and observability—not just application artifacts.

2. VPC subnet and routing architecture

A VPC contains address ranges and subnets associated with availability zones. Public-subnet designation follows routing to an internet gateway, not merely a subnet name. Private workloads often need NAT or VPC endpoints to access required services; NAT introduces cost and dependency considerations. Security groups are stateful filters attached to supported resources; network ACLs are stateless subnet-level controls. Be explicit about DNS resolution, address exhaustion, cross-zone load balancing and endpoint policies.

Why doesn't assigning an instance to a public subnet ensure internet access?

3. Compute: ECS, EKS and Lambda

ECS reduces orchestration complexity for container services; EKS provides Kubernetes APIs and portability trade-offs; Lambda suits event-driven work with bounded execution and concurrency. Select based on operational team skill, workload longevity, scaling behavior, network setup, packaging and per-request economics. Containers do not automatically solve application state or safe shutdown. Serverless concurrency can overwhelm databases without a pool or proxy strategy.

4. Load balancing and autoscaling

ALB performs Layer 7 routing and health checks; NLB has distinct Layer 4 characteristics. Use target group health and deployment draining to avoid terminating active traffic abruptly. ECS service scaling and Kubernetes HPA react to configured metrics with startup delay. CPU scaling alone may miss queueing when operations block on data. Scale asynchronous SQS workers using backlog age and service time while enforcing database connection ceilings.

How could autoscaling worsen a payment outage?

ALB → target group → replicas; SQS → worker scale subject to downstream admission budget.

5. Choosing relational, DynamoDB and object storage

RDS/Aurora suit relational constraints, rich joins and transactional access patterns; DynamoDB offers key-oriented distributed access when data modeling matches access patterns and partition capacity; S3 stores objects, not relational rows or a substitute for transactional queries. Design DynamoDB partition keys to distribute hot writes, and define transaction scope/consistency explicitly. S3 versioning supports recovery from overwrites but is not a complete immutable backup policy; lifecycle and permissions must be reviewed.

6. Events: SQS, SNS, EventBridge and Kafka

SQS is a managed queue with visibility timeouts and redrive policies; messages can be delivered again, so consumers should be idempotent. SNS and EventBridge support different pub/sub routing and integration patterns. Kafka/Kinesis offer stream-oriented ordering and replay models with operational trade-offs. Understand FIFO versus standard queue characteristics, DLQs, ordering scope, and how visibility timeout relates to processing time. Never assume an acknowledged poll means the business transaction committed.

7. AWS security, secrets and key management

Prefer workload roles and temporary credentials over embedded keys. IAM evaluates identity policies, resource policies, conditions, boundaries and organizational constraints; access decisions are not captured by a single allow statement. KMS key policy matters and cross-account decryption must be explicitly authorized. Secrets Manager supports controlled secret retrieval and rotation workflows; applications must handle refresh. Protect CloudTrail and sensitive logs from workload compromise.

8. Availability, backup and cost decision

Multi-AZ protects against certain zone-level failures but does not inherently offer multi-region recovery. Define RPO and RTO, test restore to an isolated environment, and verify backup retention plus account isolation. Cost modeling must include NAT, egress, ALB, logs, cross-AZ traffic, idle capacity and data IO, not only instance hours. A cheaper design that violates p99 or resilience requirements is not a valid optimization.

Why is multi-AZ not sufficient for regional disaster recovery?

Senior interview and design review

12 answered scenarios.

For every question, explain the failure model and demonstrate evidence before reading the model answer.

1. What makes a subnet public?

Answer before opening.
Reveal answer and exercise

A route to an internet gateway together with suitable network configuration; the subnet label alone means nothing.

Follow-up: Describe why an instance may still be unreachable.

2. Security group versus NACL?

Answer before opening.
Reveal answer and exercise

Security groups are stateful at resource interfaces; NACLs are stateless subnet controls.

Follow-up: Troubleshoot dropped return traffic.

3. What is the role of an SCP?

Answer before opening.
Reveal answer and exercise

A policy guardrail limiting account-level permissions, not an identity permission grant.

Follow-up: Why does an allow in IAM still fail?

4. When use a VPC endpoint?

Answer before opening.
Reveal answer and exercise

To reach supported AWS services privately without traversing an internet path or relying on NAT where appropriate.

Follow-up: Evaluate endpoint policies and cost.

5. Why choose ECS over EKS?

Answer before opening.
Reveal answer and exercise

A simpler orchestration experience may be preferred when Kubernetes APIs and portability are not needed.

Follow-up: Compare operational overhead.

6. Why use ALB over NLB?

Answer before opening.
Reveal answer and exercise

ALB is suited to HTTP-aware Layer 7 routing; NLB serves different transport and performance requirements.

Follow-up: Consider TLS termination and client identity.

7. How can Lambda overload RDS?

Answer before opening.
Reveal answer and exercise

Many concurrent invocations can create too many connections or high concurrent query demand.

Follow-up: Consider RDS Proxy or explicit concurrency.

8. When does SQS redeliver?

Answer before opening.
Reveal answer and exercise

A message can reappear if not deleted before visibility expires or after failures.

Follow-up: Demonstrate an idempotent worker.

9. How do you model DynamoDB keys?

Answer before opening.
Reveal answer and exercise

From known query patterns and desired partition distribution rather than from normalized table design.

Follow-up: Analyze a hot tenant partition.

10. What protects encrypted cross-account data access?

Answer before opening.
Reveal answer and exercise

Both IAM and relevant key/resource policies must authorize the operation with correct principal and conditions.

Follow-up: Diagnose KMS AccessDenied after migration.

11. Does Multi-AZ equal backup?

Answer before opening.
Reveal answer and exercise

No; redundancy and backup recovery solve different incidents.

Follow-up: Restore deleted business records after replication.

12. Where are hidden AWS costs?

Answer before opening.
Reveal answer and exercise

Data transfer, NAT processing, logs, cross-AZ IO, unused capacity and managed service charges can dominate.

Follow-up: Build a cost estimate for 100 million monthly API requests.
